PXE setup

Settings

Everything you need to set up network booting in one place. The iPXE binaries below are what targets fetch via TFTP; the snippets below tell your DHCP server which one to hand out. Once a target PXE-boots successfully, it lands on the AutoDeploy boot menu.

{{if not .Data.TFTPListening}}
TFTP listener is not configured. AUTODEPLOY_TFTP_ADDR is empty in your environment. Set it to :69 in /etc/default/autodeploy and restart the service, otherwise the iPXE binaries below won't be reachable by PXE clients.
{{end}}

These are the official, signed iPXE binaries. This server serves an autoexec.ipxe bootstrap (over TFTP and HTTP) that the stock signed iPXE fetches and runs on boot — so you do not need a custom-built binary or conditional DHCP. Just point DHCP's next-server (option 66) at this host and hand out one binary.

UEFI Secure Boot: hand out ipxe-shim.efi (a Microsoft-signed shim) instead of ipxe.efi. The shim verifies and loads ipxe.efi (use snponly-shim.efi to load snponly.efi); both must stay in this directory. With Secure Boot off, hand out ipxe.efi directly. arm64 Secure Boot uses the arm64-sb/ subdirectory.

Note: under Secure Boot, the signed iPXE will only go on to boot a signed kernel. The AutoDeploy boot-image kernel is not yet signed, so the kernel stage currently needs Secure Boot off (or the kernel enrolled). The shim still gives you a verified bootloader today. See PXE & boot → Secure Boot.

2. DHCP configuration

Tell your DHCP server to hand out the iPXE binary. Pick the section that matches your router/server. Each snippet has your AutoDeploy server's IP ({{.Data.ServerIP}}) pre-filled.

UniFi (UDM, UDM-Pro, UDR, UCG, USG)

Settings → Networks → [your LAN] → Advanced → DHCP Service → Network Boot. UniFi can only set one Boot File per network — match your fleet:

FleetBoot File
Modern UEFI x64 (~2015+)ipxe.efi
UEFI x64 + Secure Bootipxe-shim.efi
UEFI x64 with NIC driver issues / Hyper-V Gen2snponly.efi (Secure Boot: snponly-shim.efi)
Legacy BIOSundionly.kpxe
UEFI arm64ipxe-arm64.efi

Set Next Server to {{.Data.ServerIP}}.

dnsmasq (proxy DHCP, recommended for mixed BIOS/UEFI on UniFi)

Add as /etc/dnsmasq.d/autodeploy.conf:

dhcp-range=<your-subnet>,proxy
dhcp-no-override
dhcp-match=set:bios,option:client-arch,0
dhcp-match=set:uefi64,option:client-arch,7
dhcp-match=set:uefi64,option:client-arch,9
dhcp-match=set:uefiarm,option:client-arch,11
dhcp-boot=tag:bios,undionly.kpxe,,{{.Data.ServerIP}}
dhcp-boot=tag:uefi64,ipxe.efi,,{{.Data.ServerIP}}
dhcp-boot=tag:uefiarm,ipxe-arm64.efi,,{{.Data.ServerIP}}
# Secure Boot UEFI x64: hand out the Microsoft-signed shim instead:
#   dhcp-boot=tag:uefi64,ipxe-shim.efi,,{{.Data.ServerIP}}

ISC dhcpd

In your subnet block in /etc/dhcp/dhcpd.conf:

option arch code 93 = unsigned integer 16;
option user-class code 77 = string;

subnet <your-subnet> netmask <your-netmask> {
    next-server {{.Data.ServerIP}};
    if exists user-class and option user-class = "iPXE" {
        filename "http://{{.Data.ServerIP}}{{if .Data.HTTPPort}}:{{.Data.HTTPPort}}{{end}}/ipxe/boot.ipxe";
    } elsif option arch = 00:07 or option arch = 00:09 {
        # UEFI x64. For Secure Boot machines, hand out the signed shim
        # instead: filename "ipxe-shim.efi";
        filename "ipxe.efi";
    } elsif option arch = 00:0b {
        filename "ipxe-arm64.efi";
    } else {
        filename "undionly.kpxe";
    }
}

Microsoft DHCP Server

  1. DHCP console → right-click the scope → Configure Options → Advanced.
  2. Option 066 (Boot Server Host Name): {{.Data.ServerIP}}
  3. Option 067 (Bootfile Name): ipxe.efi, or ipxe-shim.efi for Secure Boot (or the right file for your fleet from the table above).

For per-arch branching, create a Vendor Class matching DHCP options 60/93 and override option 067 per class.

3. Verify it works

  1. Smoke-test TFTP from any LAN box: tftp {{.Data.ServerIP}} then get ipxe.efi (should return ~1 MB) and get autoexec.ipxe (a small #!ipxe script — generated by the server, so there's no file by that name on disk).
  2. PXE-boot a target machine. You should see an iPXE banner for ~1 second, then "=== AutoDeploy bootstrap ===" (from the served autoexec.ipxe), then AutoDeploy's boot menu.
  3. Watch the server: sudo journalctl -u autodeploy -f | grep -E "tftp|/ipxe/boot.ipxe" — you should see TFTP reads of the iPXE binary and autoexec.ipxe, then an HTTP fetch of /ipxe/boot.ipxe.

If something doesn't work

See Troubleshooting → PXE for the symptom table. The most common ones:

  • Hyper-V Gen2 "Network unreachable" after iPXE loads — swap UniFi's Boot File from ipxe.efi to snponly.efi (or vice versa). Hyper-V's synthetic NIC sometimes needs one, sometimes the other.
  • iPXE loads then sits at "Configuring (net0...)" with "autoexec.ipxe... Not found" — the server isn't serving autoexec.ipxe, or DHCP's next-server doesn't point here. Confirm get autoexec.ipxe round-trips (step 1 above) and that option 66 / next-server is {{.Data.ServerIP}}.
  • TFTP says ENOTFOUND for the binary — the iPXE binary isn't in {{.Data.IPXEDir}}. Re-run the fetch helper. Any stock binary works.
{{end}}
