Storage paths

Settings

Relocate the per-category payload trees to a different filesystem (e.g. a ZFS dataset for ISOs, an NFS mount for drivers) without rewriting the database. The relative paths the server stores stay the same; the storage layer routes each category to the configured root. Empty = use the default $AUTODEPLOY_DATA_DIR/<category>.

Files are not moved automatically. Move the existing tree to the new location before you save, or the server will look for old files in the new directory and find nothing. The save action only records the new root; it does not copy or rename anything on disk.

How to relocate without downtime

  1. Stop the AutoDeploy service so no payload writes are in flight.
  2. Move the existing directory: 
    sudo mv {{.Data.DataDir}}/<category> /new/path/<category>
sudo chown -R autodeploy:autodeploy /new/path/<category>
  3. Start the service. The directory is now empty under the data dir; saved rows still point at relative paths like iso/12/source.iso.
  4. Save the new path here. The server's blob store routes every subsequent read or write to the override; the relative paths in the database stay valid because the resolver consults the override at request time.

If you skip step 2, the server will write new uploads to the new location and existing rows will 404 because their files are in the old (now-orphaned) tree. scripts/backup.sh and scripts/windows/backup.ps1 always read the current effective paths so backups follow the override automatically.
