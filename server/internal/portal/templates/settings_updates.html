How agent self-update works

  1. The resident agent calls POST /api/v1/agent/update-info at the end of every check-in, sending its OS, arch and current version.
  2. The server scans the downloads directory for autodeploy-agent-<os>-<arch> plus a .version sidecar. If the highest available version is strictly newer than what the agent reports, the response includes a URL and SHA-256.
  3. The agent downloads the new binary to a sibling .new file. It refuses to install anything whose SHA-256 doesn't match — the hash is the only authenticator against a tampered binary.
  4. The agent writes a small platform-specific updater script (.cmd on Windows, .sh elsewhere) that waits for the agent process to exit, swaps the binary (keeping a .bak for one-step rollback), and relaunches with the same command-line.
  5. The agent spawns the updater detached and exits. The script restarts the agent on the new version within seconds.
  6. The next agent run cleans up the .bak and the script file.

Pin an agent to its current version by launching it with --no-self-update. Useful for canary testing.
