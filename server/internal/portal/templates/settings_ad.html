How AutoDeploy uses these values

When a Boot Client requests a deployment manifest and the resolved unattend has a <UnattendedJoin> section, AutoDeploy's Domain Integration Service runs the delete-and-replace lifecycle on the bound computer object before returning the manifest. That way the machine's first reboot into Windows finds the AD object exactly where the unattend expects it.

Changes here take effect on the next manifest request — no server restart needed.
